The build compiles and ESLint is clean, but I'd fix the first five items below before shipping. I only read the code and ran `tsc`, ESLint, `pnpm audit` and `next build`. I did not start Postgres or drive the app in a browser, so the runtime findings come from reading the code, and I've noted where I'm less sure. The build needs network access for Google Fonts, and `pnpm install` and `next build` left `node_modules` and `.next`, both gitignored.

## Fix before shipping

**1. The example `JWT_SECRET` passes the startup check.**
- `.env.example` has `change-me-to-a-long-random-string`, which is 33 characters. `src/lib/auth.ts:9` only rejects secrets shorter than 16, and the README says to "keep the defaults".
- If that value reaches production, anyone can mint a valid session cookie. Exploiting it also needs a victim's user id, and I didn't assess how guessable those cuids are.
- Fix: require 32 or more characters, reject the placeholder, and validate at boot. Today a missing secret is swallowed in `verifySessionToken`'s `catch`, so it shows up as a login loop rather than an error.

**2. There is no rate limiting on login or register.**
- Both routes run bcrypt at cost 12 (`auth.ts:21`), so brute force is unthrottled and each request costs real CPU.
- `login/route.ts:19` skips bcrypt when the email is unknown, so response timing reveals whether an account exists. `register` also returns 409 for an existing email.
- `register/route.ts:19` and `:28` do check-then-create. Two concurrent signups for the same email make the second hit a unique-constraint error, which is unhandled and returns a 500.

**3. Idea lifecycle rules are not enforced, and this undermines the calibration feature.**
- `PATCH /api/ideas/[id]` accepts `status` on its own (`validation.ts:33`). An idea can be marked DONE with no outcome, or set back to ACTIVE with hindsight data still attached. Calibration filters on `hindsightTotal`, not status, so an ACTIVE idea can still count.
- The Edit button (`idea-detail.tsx:120`) stays available after an outcome is recorded. Prediction scores can be rewritten after the fact, which defeats the point of the tool.
- The database doesn't back this up either. The CHECK constraints only cover the 1–5 ranges, not "outcome and hindsight are all-or-nothing".

**4. Sessions can't be revoked.**
- The JWT is stateless with a 30-day lifetime (`auth.ts:36`). Logout only deletes the cookie, so a stolen token stays valid until it expires.
- There is no password change or reset, so there is no way to invalidate sessions or recover a locked-out user.
- Fix: add a session version or token-id column checked in `getCurrentUser`, or use DB-backed sessions.

**5. There is no production database path.**
- The only migration script is `prisma migrate dev` (`package.json:12`), which is interactive and can offer to reset the database on drift. There is no `migrate deploy` script and no Dockerfile or deploy doc.
- `docker-compose.yml` publishes Postgres with the password `idealog` on all interfaces (`:10`). That is fine for local development but should say so, or bind to `127.0.0.1`.

## Should fix

- **Network failures leave the UI stuck.** No `fetch` in `auth-form`, `idea-create-form` or `outcome-form` has a `try/catch`, so a network error leaves the button on "Please wait…" or "Saving…" forever. Delete, share and logout (`idea-detail.tsx:75`, `share-control.tsx`, `logout-button.tsx:13`) ignore failures silently.
- **Validation errors are shown raw.** I confirmed that users see messages like "Too small: expected string to have >=1 characters", and only the first issue.
- **No error handling on the server.** There is no `error.tsx` or custom not-found page, and no try/catch around Prisma calls. A DB outage gives the default 500 page, and there is no logging or health endpoint.
- **No security headers.** `next.config.ts` is empty: no CSP, `frame-ancestors`, HSTS or `nosniff`, so the delete and share actions can be framed. Route handlers rely on `SameSite=Lax` alone and never check `Origin` or `Content-Type`. That is likely adequate against cross-site requests but weak against sibling subdomains.
- **Passwords are silently truncated at 72 bytes.** I confirmed two passwords that differ only after byte 72 both verify. The schema allows 200 characters (`validation.ts:5`), so users would assume all of it counts. Cap at 72 bytes or pre-hash.
- **Shared pages need hardening.**
  - `/s/[token]` has no `noindex` and no `Referrer-Policy`, and links can never expire.
  - The page queries the database twice, once in `generateMetadata` and once in the page.
  - `/api/share/[token]` is unused by the UI, and a grep found no callers, yet it duplicates the serialization and adds a public endpoint. Remove it or use it.
- **Two likely hydration mismatches.** `idea-detail.tsx:189` calls `toLocaleDateString()` in a component that is also rendered on the server. `share-control.tsx:19` renders a different URL on the server than in the browser, so the displayed link may lack the origin. I didn't confirm this in a browser.
- **Nothing is paginated.** `GET /api/ideas` and `/ideas` load every idea with full text, then re-sort in JavaScript. An invalid `?status=` is silently ignored and returns everything.

## Investigate

- **No tests and no CI.** Running `tsc --noEmit` on its own fails with `Cannot find name 'LayoutProps'` (`layout.tsx:21`), because that type is generated by `next build` or `next typegen`. CI needs a typegen step first.
- **`pnpm audit` reports one high finding.** It is `deepmerge-ts` under `prisma > @prisma/config` and only affects the CLI, not request paths. I'd still move `prisma` to `devDependencies` if the build image allows it.
- **Product gaps:** no password reset, email verification or account deletion. The last one matters for privacy obligations.
- **Repo state:** HEAD is detached, and the only commit is "raw generated build, unreviewed". The untracked `.claude/settings.json` allows `npx`, `node` and `pnpm install`, and mentions tools this repo doesn't use (`pytest`, `ruff`, `./scripts/check.sh`, which doesn't exist). Don't commit it without deciding that on purpose.

## Checked and fine

- Every idea route is scoped by `userId`, and Zod strips unknown keys, so `userId` and `shareToken` can't be mass-assigned.
- Share tokens are `nanoid(24)`, and revoking takes effect immediately because the pages are dynamic.
- The cookie is `httpOnly`, `sameSite=lax`, and `secure` in production.
- The proxy fails closed, and each page and route also checks auth itself.
- No `dangerouslySetInnerHTML` anywhere.
