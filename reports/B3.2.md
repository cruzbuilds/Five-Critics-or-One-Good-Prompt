### Should fix

**`src/lib/auth.ts`, `src/lib/session.ts`**
- `src/lib/auth.ts:10` [security-reviewer] `JWT_SECRET` only needs 16 characters, so the `.env.example` placeholder (33 characters) passes. A deployment that copies the example file signs sessions with a public key, and anyone can forge a cookie for any `sub`. Reject the known placeholder or fail in production unless the value is random, and fix the README's "keep the defaults" advice.
- `src/lib/auth.ts:8`, `src/lib/session.ts:15` [security-reviewer] Sessions are stateless 30-day JWTs and logout only deletes the cookie, so a stolen token stays valid until it expires. Shorten the TTL or add a server-side session or version check before this holds real user data.

**`src/app/api/auth/*`**
- `src/app/api/auth/login/route.ts:7`, `src/app/api/auth/register/route.ts:7` [security-reviewer] No rate limiting or lockout, and each request runs a bcrypt cost-12 hash. Credential stuffing and CPU exhaustion are both open. Add per-IP and per-account throttling.
- `src/app/api/auth/login/route.ts:20` [security-reviewer] Unknown emails return 401 without running bcrypt, so response timing reveals which emails are registered. Run `verifyPassword` against a dummy hash when the user is not found.
- `src/app/api/auth/register/route.ts:21` [security-reviewer] The distinct 409 on duplicate email lets anyone enumerate registered accounts, and it is cheap to script without rate limiting. Throttle it, or use a flow that doesn't disclose existence.
