### Blocking

**`README.md`**
- `README.md:27` [docs-reviewer, security-reviewer] The README says to fill in `JWT_SECRET` "(or keep the defaults)". It never says the secret signs session cookies, that it is required, or that it must be at least 16 characters.
  - `.env.example:2` ships `change-me-to-a-long-random-string`, which is 33 characters and passes the length guard in `src/lib/auth.ts:9`.
  - Anyone who keeps the default deploys with a published signing key and can forge a session for any user id.
  - Fix: document what the secret does and give a generation command such as `openssl rand -base64 48`. Remove "or keep the defaults". Make `getSecretKey()` in `src/lib/auth.ts` reject the placeholder.
  - Severity: docs-reviewer rated this Blocking. security-reviewer rated it Should fix and said it becomes a BLOCK if the app is ever deployed with the example value. It is kept at Blocking.

**`src/lib/calibration.ts`**

  - `i.delta ?? 0` (line 29) does the same for the total.

**`README.md`**

- `README.md:46-53` [docs-reviewer] The "Key routes" table lists only pages, not the nine `/api/**` handlers.

- `README.md:21-31` [docs-reviewer] The only run path is local dev, and `pnpm db:migrate` is `prisma migrate dev`. There is nothing on deploying:
  - No mention of `prisma migrate deploy`.
  - No mention of setting `DATABASE_URL` and `JWT_SECRET` in the target environment.
  - No mention that `NODE_ENV=production` turns on `secure` cookies (`src/lib/session.ts:17`).

  Add a short "Running in production" section. infra-reviewer noted the same absence of a deploy path.
- `README.md:59-65` [docs-reviewer] The Notes section states no limitations. List:
  - Sessions are stateless 30-day JWTs, and logout only clears the cookie (`src/app/api/auth/logout/route.ts`, `src/lib/session.ts:24`), so a stolen token stays valid until it expires.
  - There is no password reset and no email verification.
  - The share link is a bearer token that exposes the idea and its outcome.
- `README.md:61-63` [docs-reviewer] No `docs/decisions/` exists. Postgres and hand-rolled JWT/bcryptjs auth are expensive to reverse and have no recorded reasoning. Add one short ADR for each, or extend the README with the why and the consequences. scope-reviewer separately listed these same choices as probably needing ADRs.

**`docker-compose.yml`**
- `docker-compose.yml:12` [docs-reviewer, infra-reviewer] The volume `idealog_pgdata` survives `docker compose down`. `package.json` has `db:up` but no `db:down` or reset script, and the README doesn't say how to tear down. Add `db:down` (`docker compose down`) and `db:reset` (`docker compose down -v`), and document them.
- `docker-compose.yml:3` [infra-reviewer] The `db` service has no `healthcheck`. `docker compose up -d` returns before Postgres accepts connections, so a first `pnpm db:up` then `pnpm db:migrate` can fail. Add a `pg_isready` healthcheck and use `up -d --wait`.
- `docker-compose.yml:4` [infra-reviewer] `restart: unless-stopped` on a local dev database means it restarts after every reboot and runs until someone stops it. Drop it or use `restart: "no"`.
- `docker-compose.yml:6-10` [security-reviewer, infra-reviewer handed off] Postgres uses the hardcoded password `idealog` and publishes `"5432:5432"` on all host interfaces. Bind to `127.0.0.1:5432:5432` and take the password from an env var. security-reviewer rated this WARN because it is a local throwaway database, and it becomes a BLOCK if the file is used anywhere but a developer machine.

**`src/app/api/auth/login/route.ts`** and **`src/app/api/auth/register/route.ts`**
- `src/app/api/auth/login/route.ts:7` [security-reviewer] Login has no rate limiting or lockout, and `register/route.ts:7` has none either. bcrypt at cost 12 slows each guess but doesn't stop online guessing or account creation in a loop. Add per-IP and per-account throttling. test-reviewer and docs-reviewer also noticed this.
- `src/app/api/auth/login/route.ts:20-22` [security-reviewer] An unknown email returns before `verifyPassword` runs, so unknown emails respond much faster than known emails with a wrong password. - `src/app/api/auth/register/route.ts:19-25` [security-reviewer] The 409 "An account with that email already exists" reveals whether an email is registered.
