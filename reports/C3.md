I read all the source and ran lint, typecheck, audit and a production build. I couldn't run the API routes because there's no Postgres here, so the runtime behaviour below comes from reading the code. I made no edits, and the only new files are the gitignored `node_modules/` and `.next/`.

**Checks:** ESLint is clean and `next build` succeeds. `tsc --noEmit` fails on a fresh checkout (`LayoutProps` not found in `src/app/layout.tsx:21`) until `next build` or `next typegen` has run, so a CI typecheck step needs that first. `pnpm audit` reports one high finding: `deepmerge-ts` via the Prisma CLI, which is dev-time only.

## Fix before shipping

1. **The placeholder `JWT_SECRET` passes validation.** `.env.example` ships `change-me-to-a-long-random-string` (33 characters), and the README says "or keep the defaults". `getSecretKey()` in `src/lib/auth.ts:8` only rejects secrets under 16 characters, so a deploy that copies the example runs with a publicly known signing key.
   - Anyone with that key can sign a session for any user ID, and user IDs are only known to their owners.
   - The check also runs on the first request, not at boot.
   - Reject the placeholder and require 32+ characters, checked at startup. Put `openssl rand -base64 48` in the README.

2. **No brute-force protection on the auth endpoints.** Login and register have no rate limiting, and every attempt costs a bcrypt hash at cost 12, which is also a cheap CPU-exhaustion vector.
   - Login skips the hash when the email doesn't exist (`login/route.ts:22`), so response timing reveals which emails are registered.
   - Register returns a distinct 409 for existing emails, which does the same.

3. **Registration race returns a 500.** `register/route.ts` does `findUnique` and then `create`. Two concurrent requests for the same email hit the unique constraint, throw Prisma `P2002`, and return an unhandled 500. Catch `P2002` and return the 409. Since none of the routes have a try/catch, other DB errors surface as raw 500s too.

4. **The edit endpoint can break the calibration data.** `PATCH /api/ideas/[id]` (`ideaUpdateSchema`) lets a client:
   - set `status` to DONE or ABANDONED with no outcome, or back to ACTIVE while the old outcome and hindsight scores stay;
   - rewrite the prediction scores after hindsight is recorded, which defeats the "were my predictions right" purpose;
   - send `{}` and succeed, doing nothing.

   The UI never sends `status`, so only direct API calls trigger the first case. The second is reachable from the UI: Edit stays available after an outcome is recorded. Lock the prediction scores once `outcomeRecordedAt` is set, and move status changes to the outcome route only.

5. **Sessions can't be revoked, and there's no recovery path.**
   - The JWT is valid for 30 days and logout only clears the browser cookie.
   - There is no password reset, password change or account deletion.
   - bcrypt silently truncates at 72 bytes. I confirmed a 72-character password matches the same password with a different tail, while the schema accepts up to 200. Cap the password at 72 bytes.

6. **No production deploy path.**
   - The only migration script is `prisma migrate dev`. Production needs `prisma migrate deploy`.
   - There is no Dockerfile, CI, health endpoint or tests.
   - `docker-compose.yml` publishes Postgres on `5432` with `idealog/idealog` credentials. Bind it to `127.0.0.1` and make sure it never reaches a shared host.
   - `next.config.ts` sets no security headers: CSP, `X-Content-Type-Options`, `frame-ancestors`, `Referrer-Policy`.

## Should fix

- **Share links:**
  - `/s/[token]` has no `robots: noindex` and no `Referrer-Policy: no-referrer`. The token is in the URL, so it can leak to any site the viewer navigates to.
  - The public endpoints aren't rate limited.
  - Descriptions render as plain text, so I found no XSS.
  - `/api/share/[token]` duplicates the page's data logic, and no component I read calls it. Delete it or share one serializer.
- **CSRF:** protection relies on `SameSite=lax` alone. There is no `Origin` check, and the routes parse JSON without checking `Content-Type`. That's acceptable on a single origin but weak if you ever add sibling subdomains.
- **Unbounded reads:** `GET /api/ideas` and `/ideas` load every idea with full descriptions and sort in JS. Add pagination or a limit.
- **Silent failures in the client:**
  - `fetch` isn't wrapped in try/catch in the auth, create, edit and outcome forms, so a network error leaves the button stuck on "Please wait…".
  - Delete and share failures are ignored, and `navigator.clipboard.writeText` is unguarded.
- **Raw Zod messages reach users:** for example "Too small: expected string to have >=8 characters" and "Invalid email address". Map them to friendly text.
- **No error pages:** there is no `error.tsx` or custom `not-found.tsx`.
- **Invalid `?status=` is ignored:** it silently returns all ideas instead of a 400.

## Minor

- README typo: "unshareable/unguessable link".
- The score CHECK constraints exist only in raw SQL, not in `schema.prisma`. That works, but say so in the README.
- `.claude/settings.json` is untracked and allowlists tools this repo doesn't use (`pytest`, `ruff`, `checkov`). Decide whether to commit it.

Auth scoping itself looks sound. Every `/api/ideas/**` route checks the session and filters by `userId`, and the public DTO doesn't expose `userId`. `proxy.ts` is fine per the bundled Next 16 docs, since it runs on the Node runtime and isn't the only check.
